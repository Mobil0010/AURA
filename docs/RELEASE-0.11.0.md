# AURA 0.11.0 · 저사양 재생·USB 볼륨·Drive 라이브러리

## 재생 자원 사용

Android 9 이하, 저메모리 판정, 앱 메모리 등급 128MB 이하 또는 RAM 3GB 이하에서는 자원 절약 구성을 자동 적용한다. 음원 버퍼 목표 3MiB, 표지 캐시 1MiB, Drive 정보 읽기 1개 작업, 다음 Drive 곡 사전 로딩 2초를 사용한다. 일반 구성은 각각 8MiB/4MiB/2개 작업/5초다. 샘플레이트·비트 수·사용자가 켠 음향 효과는 자원 구성 때문에 바꾸지 않는다.

변환·효과가 필요 없는 정수 PCM은 DSP를 거치지 않는다. Android 기본/Hi-Res의 자동 형식에서 효과 없는 float PCM을 출력할 수 있으면 직접 전달하며, 재생 중 효과를 켜도 출력 자료형을 유지한다. USB 직접 출력은 고정 크기 원형 버퍼와 재사용 쓰기 버퍼를 사용한다. DSD의 큰 블록도 작은 단위로 비트 해제한다. 디코더 초기화 실패 시 다른 사용 가능한 디코더를 시도하고, 재생 중 CPU 절전 방지를 사용한다. 저사양에서는 재생과 함께 추가적인 Drive 태그 추출을 시작하지 않고 폴더 검색 결과를 사용한다.

## USB 비트퍼펙트

기존 PcmSink의 float 직접 지원 선언 때문에 Media3가 불필요하게 float 디코딩을 요청하고 USB 비트퍼펙트 경로에서 이를 거부하던 협상 문제를 수정했다. 16비트 등 정수 PCM을 요청하고, 알려진 24비트 무손실 FLAC/ALAC를 float로 디코딩해야 할 때는 원본 형식·샘플레이트 정보를 함께 전달한다. 원본 채널 수와 샘플레이트를 확인하고 모든 샘플이 원래 정수 격자에 정확히 들어맞는지 검사해 반올림·디더·리샘플링 없이 복원한다. 32비트 정수를 float로 낮추거나 원본 float 음원을 정수로 바꾼 뒤 비트퍼펙트라고 표시하지 않는다. 복원이 불가능하면 재생 오류로 알린다.

USB가 더 큰 슬롯만 제공할 경우 원본 비트를 버리지 않고 하위 비트에 0을 추가하는 전송 형식을 지원한다. 정확히 일치하는 인터페이스를 먼저 선택한다. 전송 상태에 슬롯 패딩을 표시한다. 실제 DAC의 아날로그 출력이나 최종 샘플 무결성을 측정한 것은 아니다.

협상 근거: [Media3 1.9.4 오디오 렌더러](https://github.com/androidx/media/blob/1.9.4/libraries/exoplayer/src/main/java/androidx/media3/exoplayer/audio/MediaCodecAudioRenderer.java). PCM 슬롯 정렬 근거: [USB-IF Audio Data Formats 1.0 §2.2.6.1](https://www.usb.org/sites/default/files/frmts10.pdf).

## 출력 엔진과 볼륨

USB 연결·분리로 Android/Hi-Res/USB 엔진, 비트퍼펙트, DSD 및 형식 설정을 초기화하지 않는다. Android/Hi-Res는 출력 기기만 전환한다. USB 직접 출력은 DAC가 없으면 선택한 엔진을 유지한 채 기다린다. 연결과 분리 각각 기본 일시정지이며 ‘재생과 알림’에서 각각 끌 수 있다. 기존에 사용자가 끈 분리 일시정지 설정은 보존한다. USB 엔진에서 DAC가 없을 때는 일시정지 옵션을 꺼도 실제 소리를 출력할 수 없다.

USB 직접 출력 전용 볼륨을 플레이어에 제공한다. 지원되는 UAC1/UAC2 Feature Unit의 볼륨을 읽고 변경 후 값을 확인한다. 모호한 라우팅·읽기 전용·서로 다른 좌우 범위는 지원하지 않는다. 지원되지 않는 DAC는 비트퍼펙트를 끈 경우에만 앱 볼륨 처리를 사용할 수 있다. 하드웨어 볼륨은 호스트 PCM을 변경하지 않으며, 앱 볼륨 처리는 PCM을 변경한다. 앱 볼륨 100%는 0dB, 50%는 -30dB, 0%는 음소거다. DAC 하드웨어 최저 값이 음소거를 뜻하는 것은 아니다.

Activity의 볼륨 키와 MediaSession의 전용 볼륨 영역으로 전경·배경 조절을 연결한다. USB 직접 출력 중 휴대폰 미디어 볼륨을 변경하지 않으므로, 엔진을 끄면 기존 시스템 볼륨을 그대로 사용한다. 하드웨어 볼륨은 첫 USB 재생 시 확인하며 그 전에는 확인 대기로 표시한다. 확인 전에는 첫 음원 버퍼를 보내지 않고, 앱 볼륨은 첫 샘플부터 저장한 레벨을 적용한다. 처음 확인할 때 임의의 최대 값으로 올리지 않는다. 직접 출력을 끄면 USB 제어 인터페이스도 해제한다. 실제 DAC의 볼륨 제어·화면 꺼짐 상태 키 동작은 실기기 확인이 필요하다.

제어 구조 확인: [Linux UAC1 정의](https://github.com/torvalds/linux/blob/master/include/uapi/linux/usb/audio.h), [UAC2 정의](https://github.com/torvalds/linux/blob/master/include/linux/usb/audio-v2.h), [Media3 시스템 볼륨 연결](https://github.com/androidx/media/blob/1.9.4/libraries/session/src/main/java/androidx/media3/session/MediaSessionLegacyStub.java).

## Drive와 시작 시 변경 확인

내장 표지를 우선하며 없으면 같은 폴더의 cover → folder → front → album → albumart → artwork 순서로 JPG/JPEG/PNG/WebP를 선택한다. 그 외 이름은 이름순으로 선택한다. 이미지 전송은 최대 4MiB이며 512px 이하 썸네일을 파일 ID·수정 시각·크기에 따라 재사용한다. 같은 폴더의 여러 곡이 같은 사진을 반복 다운로드하지 않고, 잘못된 사진도 한 검색 안에서 반복 요청하지 않는다. 연결 해제 시 관련 캐시를 지운다. 0.10.0에서 표지 플래그가 누락된 경우 기존 내장 표지를 보존한다.

Drive 태그 추출은 최대 두 작업으로 제한하고 저사양에서는 하나만 실행한다. 이미 읽은 정보·표지를 보존하고, 재생 시 완료된 정보를 다시 추출하지 않는다. 이전 곡의 대기 작업을 취소해 빠른 곡 전환 때 작업이 쌓이지 않도록 한다. 재생 중인 곡의 새 정보를 라이브러리 검색 후 반영한다.

설정의 ‘앱 시작 시 음악 변경 확인’은 기본 꺼짐이다. 켜면 등록한 로컬·Drive 폴더의 백그라운드 검색을 시작하며, 새 곡을 추가하고 삭제된 곡을 목록에서 제거한다. 성공한 검색 결과로만 해당 저장소 목록을 바꾸며 네트워크/권한 오류로 목록이 사라지지 않게 한다. 실행 중 다른 검색이 있으면 중복 시작하지 않고 화면 회전으로 다시 시작하지 않는다. 서버 푸시나 앱이 닫힌 동안의 상시 감시는 아니다. Drive 표지 추가와 기존 정보 보완에는 업데이트 후 폴더를 다시 검색한다.

## 검증 범위

테스트와 공개 배포 결과는 VALIDATION.md에 기록한다. NW-ZX507/Android 9 및 SIMGOT DEW4X 실기기는 연결되어 있지 않아 검증하지 못했다. 메모리 제한 에뮬레이터·합성 음원·모의 USB 제어와 HTTP 서버의 검증을 실기기 전체 호환성이나 무충돌 보장으로 해석하지 않는다.
