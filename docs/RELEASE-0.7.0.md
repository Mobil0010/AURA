# AURA 0.7.0 · 목록 스크롤과 Drive 다음 곡 준비

곡·앨범·아티스트·폴더 및 그룹 곡 목록과 Google Drive 폴더 선택 화면에서 안쪽 목록의 드래그가 화면 전체 스크롤에 가로채이던 문제를 수정했다. 외부 화면을 NestedScrollView로 바꾸고 제한 높이의 RecyclerView에 중첩 스크롤을 활성화했다. 목록 끝에서는 남은 드래그와 플링을 화면으로 넘겨 아래 안내나 위쪽 계정·폴더 설정까지 이동할 수 있다. 행 재활용과 플레이어 앨범 표지의 아래로 닫기 제스처는 유지한다.

다음 재생 대상이 Google Drive 곡이면 Media3의 [플레이리스트 사전 로딩](https://developer.android.com/blog/posts/elevating-media-playback-introducing-preloading-with-media3-part-1)을 사용해 약 5초 분량의 샘플을 메모리에 준비한다. 현재 재생 데이터 로딩을 우선하며 여유가 있을 때 미리 읽는다. 전환할 때 준비된 샘플을 같은 플레이어에서 재사용하며 별도 음원 파일이나 영구 캐시를 만들지 않는다. 대기열 변경·다음 곡 이동·셔플·반복 설정에 따라 대상을 다시 계산한다. 마지막 Drive 곡으로 넘어갈 때도 설정을 유지해 준비된 버퍼가 인수 전에 해제되지 않도록 하며, 대기열이 비면 해제한다. 연결 해제 시 기존 Drive 대기열 제거 경로로 정리한다.

네트워크가 느리거나 다음 곡을 너무 빨리 선택하면 버퍼링이 남을 수 있다. 이 기능은 무손실 재생이나 DAC의 물리적 무간격 출력을 보장하는 검증이 아니다. Google 로그인 계정 제한과 Drive의 DSD/Cast 제한은 0.6.0과 같다.

검증: Android 16 ARM64에서 전체 72개 검사 통과. 실제 터치로 라이브러리 4개 탭과 긴 그룹 목록 및 Drive 폴더 선택의 양 끝·페이지 상하단을 검사했다. 모의 Drive 서버와 실제 재생 엔진으로 사전 로딩, 데이터 재사용, 대기열 교체 및 자동 다음 곡 전환을 확인했다. APK 서명은 기존 키를 유지했고 Lint 오류는 0개다. 실제 Google 계정의 실기기 재생 검증은 별도다.
