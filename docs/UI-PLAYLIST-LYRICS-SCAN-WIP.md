# 플레이리스트·전체화면 가사·시작 시 증분 확인 — 개발 이력

2026-10-27 작업. 사용자 요청에 따라 로컬 앱과 검증까지만 진행했다. 로컬 버전 0.12.0/code16을 유지하며 GitHub 게시·배포 파일 준비·공개 update.json 변경은 하지 않았다. 이전 홈·라이브러리·설정·EQ UI 변경도 포함된 작업 폴더다.

## 화면과 가사

- 플레이리스트는 공통 둥근 카드, 정사각형 표지, 곡 수, 독립된 더보기 버튼으로 구성했다. 생성·이름 변경·삭제 확인 및 빈 목록 안내를 제공한다. 곡 URI 배열은 유지하며 곡 매핑을 한 번만 구성한다. 상세 화면은 표지·재생 버튼·곡 목록을 같은 스타일로 정리했다.
- 전체화면 가사는 큰 글자와 현재 줄의 파란 강조를 사용한다. 다크·라이트를 모두 지원한다.
- 곡 정보와 이전/재생·일시정지/다음 컨트롤은 가사 위에 겹치는 카드다. 화면 진입 및 가사 터치·스크롤 후 나타나고 마지막 조작 약 3초 뒤 숨는다. 나타남 220ms, 사라짐 260ms의 이동·투명도 애니메이션을 사용한다. 가사 본문의 크기나 위치를 바꾸지 않으며 앱의 애니메이션 설정을 따른다.
- 전체화면의 ‘단어 강조’ 스위치는 즉시 반영되고 저장된다. 끄면 현재 줄 전체를 강조한다. 사용자가 직접 가사를 움직이면 자동 따라가기를 5초 동안 쉬었다가 다시 이어간다.
- enhanced LRC의 단어 시간이 있으면 해당 시간에 맞춰 글자 영역을 순차적으로 채운다. 줄 시간만 있으면 줄 사이 구간을 단어 길이에 따라 나누며 **‘줄 기준 추정 강조’**로 표시한다. 음성 인식이나 실제 발음 정렬은 수행하지 않는다. LRCLIB의 줄 가사가 항상 정확한 단어 시간을 제공한다고 가정하지 않는다.
- 강조는 기존 글자 배치를 재사용하고 현재 줄만 다시 그린다. 매 틱마다 전체 가사 문자열이나 강조 span을 만들지 않는다. 탐색 시 이전 위치로 돌아갈 수 있고 유니코드 보조 문자를 분리하지 않는다.
- 작은 표지의 대체 이미지는 음표만 표시해 앨범명이 잘리는 현상도 정리했다.

## 시작 시 새 음악만 확인

설정의 시작 시 변경 확인으로 실행되는 경로만 새 곡 전용이다. 기존 곡은 재생 시간 0, 미완료 메타데이터, 없는 표지 캐시 등의 상태여도 자동으로 다시 분석하지 않는다. 기존 곡의 태그와 표지는 그대로 유지한다. 사용자가 직접 실행하는 검색은 기존 캐시·재분석 동작을 유지한다.

- **Drive:** 계정·등록 루트·폴더 목록과 변경 커서를 저장한다. 다음 시작에는 changes API로 변경을 확인한다. 관련 변경이 없으면 폴더 목록·음원·표지를 다시 요청하지 않는다. 관련 변경이 있으면 영향받은 폴더 및 새 하위 폴더만 읽고 새로운 파일 ID만 분석한다. 기존 파일의 이름이 바뀌어도 새 음원으로 간주하지 않는다.
- 이전 인덱스에서 첫 전환 시 폴더 목록을 한 번 구성한다. 이때도 기존 음원 정보는 다시 열지 않는다. 커서가 무효이거나 등록 루트가 바뀌면 같은 방식으로 목록을 재구성한다. 공유 드라이브 단위 변경 등 범위를 특정할 수 없는 이벤트는 저장한 폴더 목록을 확인한다.
- **기기 저장소:** 일반 SAF 제공자에는 공통 변경 피드가 없어 파일·폴더 목록은 확인해야 한다. 저장된 문서 ID와 비교해 새 음원만 열고 기존 음원의 메타데이터·표지를 건너뛴다. 변경이 없으면 인덱스를 다시 저장하거나 화면 갱신을 요청하지 않는다.
- 정상적으로 확인된 삭제 항목은 제거한다. 폴더 조회나 Drive 변경 페이지가 실패하면 기존 인덱스와 변경 커서를 유지한다. 재생 중 갱신된 Drive 태그가 있으면 최종 저장 시 합친다.

Drive API 근거: [변경 기록 사용](https://developers.google.com/workspace/drive/api/guides/manage-changes), [changes.list](https://developers.google.com/workspace/drive/api/reference/rest/v3/changes/list).

## 검증

- assembleDebug / assembleDebugAndroidTest / lintDebug 성공. Lint 오류 0 / 경고 41.
- 순수 Java 검사: 기존 코어 11개, 단어 타이밍 8개, 리모컨 HTTP 21개 통과.
- API 36 ARM64 / CPU 2코어·RAM 2GB 설정에서 첫 새 기능·환경 검사 8개 통과(37.207초). 기존 검색·Drive·폴더 표지·가사·스크롤 회귀 53개 통과(168.993초).
- 작은 표지 대체 문구만 추가로 바꾼 최종 앱에서도 증분 검색 3개와 출력·표지·아이콘·제스처 9개를 통과했다. 같은 실행의 플레이리스트 메뉴 검사는 실패하여 전체 실행 통과로 세지 않았다. 존재하지 않는 테스트 클래스명 지정 오류도 별도로 수정했다.
- 대화상자에 시스템 뒤로가기/접근성 입력을 보내는 새 검사는 창을 안정적으로 찾지 못해 제거했다. 최종 플레이리스트 검사는 메뉴 버튼 연결, 카드→상세→복귀, 저장 곡 목록 유지만 검사한다. 메뉴 생성·이름 변경·삭제의 실제 대화상자 조작은 자동 검증 범위에 포함하지 않는다.
- 최종 테스트 APK에서 플레이리스트·가사 4개 통과(33.612초). 최종 앱의 고유 재확인 범위는 증분 검색 3개·출력/표지 UI 9개와 합쳐 16개다. 이전 회귀 53개를 작은 표지 변경 후 전부 재실행했다고 주장하지 않는다.
- 신규 검색 검사에서는 수정일·크기가 없는 로컬 파일, 재생 시간 0/미완료 Drive 태그/없는 표지를 포함해 기존 음원을 다시 여는 횟수가 0인지 확인했다. 추가 곡만 분석하고 삭제 곡을 제거하며, Drive 변경 없음의 폴더 요청 0회 및 변경 페이지 실패의 기존 인덱스·커서 보존을 확인했다.
- 두 테마의 플레이리스트·가사 컨트롤·숨김 화면을 캡처했다. 단어 강조 켜기/끄기의 저장과 스크롤 유지, 앞뒤 탐색 시 강조 위치, 추정 표시, 직접 스크롤의 컨트롤 노출 및 약 3초 뒤 숨김, 다른 화면 이동 후 타이머 정리를 확인했다.

실제 NW-ZX507이나 사용자의 Drive 계정 데이터로 성능을 측정한 것은 아니다. 오디오 엔진과 네이티브 USB 코드는 변경하지 않았다.
