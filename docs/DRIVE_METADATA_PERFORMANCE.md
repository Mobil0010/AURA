# Drive 음악 정보 읽기 개선 — 미배포

2026-10-29. 공개 릴리스와 업데이트 피드는 사용자 요청대로 변경하지 않았다. 기존 0.20.1/code27 개발 후보에 포함한다.

## 변경

- FLAC은 STREAMINFO·Vorbis Comment·PICTURE 메타데이터 블록을 직접 읽는다. 제목·아티스트·앨범·장르·트랙/디스크 번호·재생 시간·원본 샘플레이트/비트 깊이·앨범아트를 얻기 위해 Android 디코더로 오디오 프레임을 탐색하지 않는다.
- 작은 앞부분 요청은 16KiB만 받아 재사용한다. 표지 등 큰 영역은 기존 256KiB 블록을 사용한다. 곡별 4MiB 전송 한도와 최대 4개 메모리 블록(1MiB 이하)은 유지한다. 파일 크기가 알려지지 않으면 별도 크기 조회가 필요할 수 있다.
- 일반 기기의 동시 메타데이터 분석은 기존 2개에서 최대 4개로 늘린다. Android 9 이하/저메모리 등 자원 절약 기기는 기존 1개를 유지한다. 재생 자체의 버퍼·음질 설정은 변경하지 않는다.
- 성공한 분석은 formatChecked 상태도 저장한다. 변경 없는 곡을 다시 검색할 때 태그·Hi-Res 정보·표지를 재사용하고, 앱 시작 증분 확인은 기존 곡의 일괄 재분석을 하지 않는다.
- FLAC을 확인하지 못했거나 재생 시간을 얻을 수 없는 파일 등은 기존 MediaMetadataRetriever 경로로 처리한다. FLAC 외 포맷도 기존 분석기를 사용한다. 취소·계정 변경 검사는 유지한다.

## 범위와 제한

태그 블록은 최대 1MiB, 빠른 경로의 개별 표지 블록은 최대 3MiB로 제한한다. 지나치게 큰 표지는 태그를 읽기 위해 전부 다운로드하지 않으며, 기존에 보관한 표지나 폴더 표지를 사용할 수 있다. 파일에 적힌 길이·개수는 읽기/할당 전에 검사한다.

Google API 응답 지연·계정별 제한·네트워크 속도는 앱이 제어할 수 없다. 개선은 태그 분석 요청과 불필요한 전송을 줄이는 것이며 실제 사용자 계정에서 일정 배수의 속도 향상을 보증하지 않는다. 폴더 목록 페이지 요청은 기존 방식을 유지한다.

검사는 DriveMetadataSpeedTest와 기존 Drive 스트리밍·태그 예산·폴더 표지·증분 검색·앨범아트 영구 보관 회귀 검사로 수행한다. 실제 검사 결과와 로그는 VALIDATION.md에 기록한다.
