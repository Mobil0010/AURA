# 앨범아트·곡 정보·출력 형식·기억 기능 — 미배포

2026-10-27. 사용자가 화면 캡처 확인 전 배포를 보류하도록 요청했다. 구현과 검증까지만 수행했으며 버전은 0.16.0/code20 그대로다. 이 로컬 APK는 공개 0.16.0 APK와 다른 미배포 빌드이며 dist/공개 릴리스/업데이트 피드는 변경하지 않았다.

## 변경

- 앨범아트 저장 한도를 512px에서 2048px로, JPEG 품질을 85에서 95로 높였다. 작은 원본은 확대하지 않는다. 기존 2의 거듭제곱 샘플링 때문에 실제 저장 크기는 원본에 따라 2048px보다 작을 수 있다.
- 화면에서 실제 측정한 크기로 디코딩한다. 일반 기기는 최대 2048px, 메모리가 제한된 기기는 최대 1024px이며 기존 메모리 캐시 예산은 늘리지 않았다. 큰 표지를 캐시에 넣어 작은 썸네일까지 밀어내지 않도록 했다. ARGB_8888과 필터링을 사용한다. 1:1 배치 및 원본 비율을 유지하는 CENTER_CROP을 유지했다.
- 큰 플레이어 표지에서만 기존 저화질/누락 캐시를 선택적으로 보완한다. 현재 캐시를 먼저 표시하고 원본 읽기는 별도 제한된 백그라운드 큐에서 수행한다. 실패하면 기존 표지를 유지한다. 로컬 내장 표지와 Drive 내장/같은 폴더 사진을 지원한다. 이미 처리한 작은 원본은 마커로 식별한다. 전체 음악을 앱 시작 때 다시 읽지 않으며 기존 Drive 변경 확인의 기존 폴더 표지를 일괄 재다운로드하지 않는다. 온라인 앨범아트 검색은 추가하지 않았다.
- 점 세 개 메뉴에 곡 정보를 추가했다. 앨범아트·곡 제목·아티스트와 아이콘 메뉴를 AURA 둥근 카드로 구성했다. MainActivity의 기존 기본 선택/확인창도 AppCompat 공통 테마를 사용한다.
- 곡 정보는 파일에서 읽은 태그, 크기, 코덱, 샘플레이트, 비트 깊이, 채널, 비트레이트, 재생 시간, 폴더/주소를 제공하며 복사할 수 있다. 핵심 음질 정보는 위쪽 2열 카드로 표시한다. WAV/FLAC/DSF 헤더로 원본 값을 보완한다. 손실 압축의 비트 깊이는 해당 없음으로, 알 수 없는 값은 확인 불가로 표시한다. 출력 엔진 설정을 원본 정보로 사용하지 않는다. Drive 조회는 기존 4MiB 전송 한도의 범위 읽기를 재사용한다.
- 플레이어에 입력 PCM → 앱 출력 형식을 표시한다. PcmSink에서 실제 출력 생성이 성공한 뒤 확정된 형식을 사용하며 SoX/호환 리샘플링, 비트 형식 변환을 표시한다. 실패/대기 시 이전 수치를 유지하지 않는다. 시스템 믹서나 DAC 내부의 최종 출력 형식을 측정했다는 의미가 아니다. 캐스트의 최종 형식은 확인 불가로 표시한다.
- 마지막 라이브러리 탭, 저장소, 저장소별 폴더 경로를 기억한다. 새 Activity로 앱을 열거나 홈의 폴더 바로가기를 눌러도 복원한다. 삭제된 폴더는 가까운 남은 상위 폴더로 복귀하며 검색 중 임시 결과로 기억 경로를 덮어쓰지 않는다.
- USB DAC 하드웨어 볼륨을 기기별로 기억한다. USB VID/PID·버전·일련번호(없으면 모델명)와 볼륨 제어 유닛으로 키를 만들고, 적용/확인된 실제 하드웨어 값을 저장한다. 재연결 시 지원 범위/간격에 맞춰 복원·재확인한다. 복원 실패 시 저장값을 보존하고 안내한다. 볼륨 확인 중 기존 PCM 대기 동작을 유지하며 소프트웨어 게인과 Android 미디어 볼륨은 사용하지 않는다. 일련번호가 없는 같은 모델 여러 대는 같은 기억값을 공유할 수 있다.

## 검증

- assembleDebug·assembleDebugAndroidTest·lintDebug 성공. lint 오류 0 / 경고 48.
- API36 ARM64, CPU2/RAM2GB 에뮬레이터에서 관련 48개 통과, 106.782초: 앨범아트 5, Drive 폴더 표지 6, 곡 정보/실제 SoX 표시/양 테마 5, 폴더 기억 2, 하드웨어 볼륨 기억 2, 기존 재생 안정성 7, 증분 검색 3, 저사양 UI 8, EQ/테마/메인 스레드 파일 접근 6, 폴더/공통 선택창 3, 환경 1.
- 이후 곡 정보 카드 정리 및 WAV/손실 압축 표기 변경 후 곡 정보/캡처·폴더 기억·DAC 볼륨 기억 9개를 다시 실행해 통과, 19.516초. 마지막에는 캐스트 입력의 ‘원본’ 단정 문구만 중립적인 ‘음원 전송’으로 수정하고 빌드/lint를 재확인했다. 48개 전체를 마지막 문구 수정 후 다시 실행했다고 주장하지 않는다.
- 실제 FLAC에 2048px PICTURE 블록을 넣고 기존 256px 표지가 큰 화면에서 2048px 파일로 보완되는 것을 확인했다. 4096×2048 입력이 2048×1024로 저장되고 작은 원본은 확대되지 않는지, 900px 배치에서 저사양 디코딩이 900px 이상·1024px 이하인지 검사했다. 기존 표지의 오프라인 유지와 UI bind의 StrictMode 디스크 접근 금지도 확인했다.
- 실제 WAV를 재생하며 SoX 192kHz/24bit 출력이 열린 뒤 플레이어에 반영되는 것을 확인했다. 실제 24bit/48kHz FLAC의 원본 정보 및 DSF 표기도 검증했다.
- 폴더는 로컬/Drive 인덱스를 넣고 Activity를 완전히 끝낸 후 새 Activity를 열어 경로와 홈 바로가기 복원을 확인했다. DAC는 USB 제어 모형으로 적용 확인값 저장, 재연결 복원, 기기 A/B 분리, 복원 실패 후 재시도를 검사했다.
- NW-ZX507 및 실제 USB DAC/캐스트 기기의 이번 동작은 미검증이다. 실제 USB DAC의 일련번호 제공 여부·쓰기 지원·펌웨어 동작에 따라 복원이 제한될 수 있다.
