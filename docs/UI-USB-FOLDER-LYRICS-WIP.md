# USB 엔진·폴더 표지·가사 초기화 — 개발 이력

2026-10-28. 사용자 최신 지시에 따라 구현·검사·실제 앱 캡처까지만 수행했다. **배포하지 않았으며 버전은 0.17.0/code21 그대로**다. 공개 APK 및 업데이트 피드, dist 파일은 변경하지 않았다. 이 로컬 APK는 공개 0.17.0과 다른 미배포 빌드다.

## 출력 엔진

- USB 오디오 기기가 없으면 출력 엔진 선택창의 USB DAC 직접 출력 항목을 흐리게 표시하고 실제 선택도 차단한다. 선택 순간 다시 연결 여부를 확인한다.
- USB 직접 출력에 들어가기 직전의 Android 기본 또는 Hi-Res AudioTrack 엔진을 기억한다. DAC를 분리하면 그 엔진으로 복귀한다. 비트퍼펙트/DoP 전용 설정 때문에 폰 출력이 막히지 않도록 복귀 시 해당 경로 제약을 해제한다. 기존 USB 연결/분리 시 일시정지 설정은 유지한다.
- USB 직접 출력에서 Android 기본/Hi-Res AudioTrack을 선택하면 USB 전용 비트퍼펙트·DoP 제약을 먼저 해제하고 재생 위치와 재생/일시정지 상태를 보존해 적용한다. 명시적으로 시스템 엔진을 선택한 경우 자동 USB 재선택 때문에 곧바로 되돌아가지 않도록 선호도를 갱신한다.
- 앱 시작 시 DAC가 없는데 USB 엔진이 저장돼 있으면 재생 준비 전에 이전 시스템 엔진으로 복구한다. 기존 직접 출력 선호가 있고 재연결 기기에 권한이 있으면 자동 연결 경로를 사용한다. 권한이 없으면 사용자 권한 허용이 필요하다.

## 폴더 표지와 성능

- 정렬된 라이브러리로 폴더 트리를 구성할 때 각 폴더의 첫 곡 참조를 한 번만 정한다. 목록 바인딩에서 하위 곡을 매번 순회하거나 정렬하지 않는다. 하위 폴더까지 포함한 해당 폴더 재생 순서의 첫 곡을 사용한다.
- 기존 폴더 아이콘 자리에 첫 곡의 표지를 표시한다. 읽을 수 있는 표지가 없으면 기본 폴더 아이콘을 유지한다. 재활용되는 셀은 같은 ArtworkView를 바인딩하고 이전 작업의 늦은 결과를 차단한다.
- 내장 표지가 없으면 같은 폴더의 cover/folder/front 등의 JPEG/PNG/WebP 사진을 사용한다. 로컬 SAF 검색에서 폴더당 사진 후보를 한 번 수집한다. 이미 곡 메타데이터가 캐시된 경우에도 음원을 다시 열지 않고 사진만 보완한다.
- 기존 인덱스의 누락 표지는 보이는 폴더에서만 백그라운드로 보완한다. 로컬 부모 폴더 후보는 제한된 캐시에 보관한다. Drive는 저장된 폴더 목록을 재사용하고, 목록이 없는 예전 인덱스는 해당 폴더만 조회한다. 기존 내장 표지 기록이 있고 이미지 캐시가 지워진 경우 원본 표지를 우선 복원한다.
- 이미지 조회·디코딩·복원은 UI 스레드에서 수행하지 않는다. 폴더 아이콘은 측정된 실제 표시 픽셀 크기(최대 256px)만 디코딩한다. 기존 저사양 이미지 캐시 예산을 늘리지 않았다. 제한된 작업 큐와 재활용 시 요청 무효화를 사용한다.
- 한 폴더 사진은 한 번 정규화해 공유한다. 같은 앱 파일 시스템의 하드 링크를 우선 사용하고 지원하지 않으면 복사한다. 매 곡마다 같은 고해상도 사진 데이터를 중복 저장하는 부담을 줄였다. 읽기와 디코딩은 16MiB 입력/2048px 저장 상한을 유지한다.
- 캡처에서 확인한 정렬 버튼의 영문 ‘sort’ 표시도 아이콘으로 수정했다.

## 전체화면 가사

곡 전환 시 이전 곡의 스크롤 오프셋을 복원하지 않는다. 새 가사 창을 맨 위에서 시작하고 이전 수동 스크롤 대기 상태를 갱신한다. 가사 로딩 후 다시 렌더링될 때도 새 창의 맨 위를 유지한다. 같은 곡의 단순 메뉴/메타데이터 갱신에는 기존 위치를 유지한다. 네트워크 재생의 곡 식별자 변경도 확인한다.

## 검사

- assembleDebug·assembleDebugAndroidTest·lintDebug 성공. lint 오류 0 / 경고 48.
- 초기 관련 14개 통과 후 기존 재생 안정성·증분 검색·EQ/테마·저사양 UI·폴더/가사 동작·폴더 기억 회귀 검사 **36개 통과**, 124.901초.
- 마지막 재검사에서 기존 메타데이터 캐시 경로가 새 폴더 사진을 적용하지 않는 문제를 발견해 수정했다. 선택창 검사는 고정 대기 대신 접근성 창 생성 완료를 기다리도록 보완했다.
- 최종 APK에서 환경 1, 새 USB/폴더/가사 검사 6, Drive 표지 7, 증분 검색 3, 재생 안정성 7, **총 24개 통과**, 57.811초. 이전 36개 전체를 마지막 수정 후 다시 실행했다고 주장하지 않는다.
- API36 ARM64 / CPU2·RAM2GB 에뮬레이터를 사용했다. 실제 USB DAC/NW-ZX507/사용자 Drive 계정은 검증하지 않았다.
- USB 미연결 행의 실제 disabled 상태, 이전 Android/Hi-Res 엔진 복귀, USB 설정에서 시스템 엔진 선택 시 비트퍼펙트/DoP 해제, 정렬된 첫 곡 참조, SAF 폴더 사진을 음원으로 오인하지 않는지 검사했다. 메타데이터 캐시가 있는 곡에서 새 사진을 적용하면서 원본 WAV 열기 횟수가 증가하지 않는 것도 확인했다.
- Drive 표지 누락을 저장된 폴더 목록에서 보완하면서 오디오 메타데이터 읽기 횟수와 라이브러리 revision이 증가하지 않는지 검사했다. 기존 내장 표지 보존·폴더 사진 공유·고해상도 보완 검사도 통과했다.
- 실제 MediaController 대기열에서 50줄 LRC의 첫 곡을 아래로 스크롤한 뒤 다음 곡을 선택해, 새 가사 로딩 후 스크롤 Y가 0인지 확인했다.
